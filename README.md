# Power Theft Detection System Using MATLAB/Simulink

A BTech electrical/electronics project that simulates a single-phase distribution network and detects a suspected unmetered connection by comparing source current with the sum of registered consumer currents.

## Project overview

The Simulink model contains a single-phase AC source, a distribution feeder, four registered consumer branches, current sensors, and a controllable unmetered branch that represents a suspected illegal tap. Measured currents are passed to a detection algorithm that calculates the current mismatch and its rolling RMS value. An alarm is raised when the RMS mismatch exceeds a calibrated threshold.

> **Scope:** This is a simulation project. A current mismatch indicates an unexplained measurement residual; it does not by itself prove electricity theft in a real network. Sensor errors, timing differences, feeder losses outside the measurement boundary, or legitimate unmetered loads can also create mismatches.

## Tools

- MATLAB
- Simulink
- Simscape Electrical

## How the method works

1. Measure the source current and the four registered-load currents.
2. Synchronize measurements and maintain consistent current-sensor polarity.
3. Calculate the instantaneous residual:

   `mismatch = source current - (load 1 + load 2 + load 3 + load 4)`

4. Calculate the rolling RMS of the residual.
5. Compare the RMS mismatch with the calibrated threshold and output a suspected-theft flag.

The unmetered branch is downstream of the source sensor but is intentionally excluded from the sum of registered consumer currents.

## Files

Upload the following files to this repository (use the filenames that exist in your project folder):

- `power_theft_simulink_2.slx` — main Simulink model used for the circuit tests.
- `power_theft_demo.m` — standalone MATLAB baseline demonstration using synthetic test signals. Its results are not the same as the Simulink results below.

- `tune_threshold.m` — script used to estimate a threshold from recorded normal-operation RMS-mismatch data. It expects `normalMismatchRMS` in the workspace; when using simulation output logging, assign it from the logged output first, for example `normalMismatchRMS = out.normalMismatchRMS;`.
- `power_theft_demo_results.csv` — optional CSV output generated by `power_theft_demo.m` when that script is run.

## Running the project

1. Download or clone this repository.
2. Open MATLAB and set the project folder as the Current Folder.
3. Open `power_theft_simulink_2.slx` and run the Simulink model. Simscape Electrical must be installed for the physical electrical circuit.
4. For threshold calibration, run a separate simulation with the unmetered branch kept OFF throughout the run and log the `mismatchRMS` output to a Timeseries variable named `normalMismatchRMS`.
5. If the run logs its signals inside a Simulink output object named `out`, assign `normalMismatchRMS = out.normalMismatchRMS;` in the MATLAB Command Window, then run `tune_threshold`.
6. Enter the calibrated threshold in the MATLAB Function detector, then test with the unmetered branch switched ON and OFF.

The included `power_theft_demo.m` can be run separately with:

```matlab
power_theft_demo
```

It generates synthetic signals, plots the baseline detector behaviour, prints sample-wise performance metrics, and writes `power_theft_demo_results.csv`. These synthetic results should not be presented as the Simulink model's measured results.

## Simulink test results

The following sample-wise metrics were recorded from one Simulink test scenario:

| Metric | Result |
|---|---:|
| True positives (TP) | 4,395 |
| True negatives (TN) | 7,406 |
| False positives (FP) | 195 |
| False negatives (FN) | 5 |
| Total samples | 12,001 |
| Accuracy | 98.33% |
| Precision | 95.75% |
| Recall | 99.89% |
| False-positive rate | 2.57% |

In additional tests, the alarm flag changed to `1` for unmetered branches using 230 Ω and 460 Ω resistors. The nominal currents at 230 V RMS are approximately 1.0 A and 0.5 A, respectively; actual currents depend on the feeder impedance and voltage at the tap.

These results describe the tested simulation conditions only. Accuracy is sample-wise, and samples around the switching events can be affected by the rolling RMS window and its delay. Additional validation is needed under normal load changes, sensor noise, measurement errors, and a wider range of theft currents.

## Possible future improvements
